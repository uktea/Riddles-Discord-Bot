# なぞなぞBot

Discordサーバー内で、なぞなぞの出題・回答・期限管理を行うBotです。問題ごとに公開スレッドを作り、参加者はスレッド内の「回答する」ボタンから回答します。

次の3種類の出題に対応します。

- `/briddle`: 指定人数の正解者が出た時点で回答受付を終了し、正解と正解までの所要時間を発表します。正解人数と誤答の公開方法を問題ごとに設定できます。
- `/riddle`: 期限まで複数人の正解を受け付け、期限になった時点で正解と最初の正解までの所要時間を発表します。回答の公開、出題者による別解採用、1人あたりの回答回数を設定できます。
- `/ogiri`: 固定の正解を持たない大喜利です。回答を公開し、出題者が期限までに採用回答とMVPを選びます。

いずれも問題へ画像・音声・動画を1ファイル添付できます。受付中の問題には、文章またはメディアによるスポイラー形式のヒントも追加できます。結果発表後は回答ボタンだけを無効化し、スレッドは感想戦用に開いたままにします。結果発表後も問題IDとDiscordスレッドの紐付けはスレッドが削除されるまでSQLiteに保持されるため、Botの `/delete` で後から完全削除できます。

## 動作要件

- Python 3.11以上
- Discord Botを追加できるテスト用または運用用サーバー
- Botを動かし続けるWindowsまたはLinux PC
- インターネット接続

主な依存パッケージは `discord.py` と `python-dotenv` です。SQLiteはPython標準ライブラリを使用するため、別途データベースサーバーを用意する必要はありません。

## Discord側の準備

### 1. Botを作成する

1. [Discord Developer Portal](https://discord.com/developers/applications)を開きます。
2. `New Application` からアプリケーションを作成します。
3. 左側の `Bot` を開き、Botユーザーを作成します。
4. `Reset Token` または `View Token` からトークンを取得し、後述する `.env` の `DISCORD_TOKEN` にだけ保存します。

Botトークンはパスワードと同じ秘密情報です。チャット、スクリーンショット、ソースコード、Gitのコミットには絶対に含めないでください。漏えいした可能性がある場合は、Developer Portalで直ちにトークンを再生成してください。

### 2. 回答方式を確認する

このBotの回答は、スレッド内のボタンとModal（入力フォーム）で受け付けます。Developer PortalのPrivileged Gateway Intentsを追加で有効にする必要はありません。

### 3. Botをサーバーへ招待する

Developer Portalの `OAuth2` → `URL Generator` または `Installation` で、次を設定します。

Scopes:

- `bot`
- `applications.commands`

Bot Permissions:

- View Channels
- Send Messages
- Create Public Threads
- Send Messages in Threads
- Read Message History
- Manage Threads
- Add Reactions
- Attach Files
- Use Application Commands

`Add Reactions` は問題投稿と公開回答へ設定済みの評価絵文字を付けるため、`Attach Files` は問題やヒントへメディアを添付するために使用します。生成されたURLを開き、対象サーバーへBotを追加します。運用チャンネル側で権限を個別に上書きしている場合は、上記の権限がそのチャンネルと公開スレッドでも許可されていることを確認してください。

## セットアップ

OS別の詳しい手順は次を参照してください。

- [Windowsセットアップ](docs/WINDOWS_SETUP.md)
- [Linuxセットアップ](docs/LINUX_SETUP.md)

最小手順は次のとおりです。

```text
python -m venv .venv
```

仮想環境を作成したら、その仮想環境のPythonで依存パッケージをインストールします。実行ファイルの場所はOSによって異なります。

```powershell
# Windows
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

```bash
# Linux
./.venv/bin/python -m pip install -r requirements.txt
```

`.env.example` を `.env` という名前でコピーし、必要な値を入力します。

```dotenv
DISCORD_TOKEN=
DISCORD_GUILD_ID=
DATABASE_PATH=data/riddles.db
LOG_LEVEL=INFO
```

`DISCORD_TOKEN=` の右側には取得したBotトークンを入力します。トークンそのものを他のファイルへ貼り付けないでください。

設定後、プロジェクトのルートディレクトリで起動します。

```powershell
# Windows
.\.venv\Scripts\python.exe main.py
```

```bash
# Linux
./.venv/bin/python main.py
```

正常にログインし、スラッシュコマンドの同期が完了したことをログで確認してください。

## 環境変数

| 変数 | 必須 | 既定値 | 説明 |
| --- | --- | --- | --- |
| `DISCORD_TOKEN` | はい | なし | Discord Botの秘密トークン。空のままでは起動できません。 |
| `DISCORD_GUILD_ID` | 推奨 | なし | コマンドの同期先と利用を許可するサーバーID。テスト用・単一サーバー運用では設定を推奨します。 |
| `DATABASE_PATH` | いいえ | `data/riddles.db` | SQLiteデータベースの保存先。相対パスはプロジェクトルート基準です。 |
| `LOG_LEVEL` | いいえ | `INFO` | ログレベル。`DEBUG`、`INFO`、`WARNING`、`ERROR`、`CRITICAL`を指定できます。 |

サーバーIDはDiscordの「ユーザー設定」→「詳細設定」→「開発者モード」を有効にし、対象サーバーを右クリックして「サーバーIDをコピー」すると取得できます。サーバーID自体は秘密情報ではありません。

`DISCORD_GUILD_ID` を設定すると、そのサーバーへコマンドを同期するため、開発・単一サーバー運用で変更が反映されやすくなります。未設定時はグローバル同期となり、Discord上への反映に時間がかかることがあります。

この値はDiscord Gatewayへの接続先ではありません。Botは、同じBotアカウントが招待されているサーバーへGateway経由で接続します。`DISCORD_GUILD_ID` を書き換えただけでは運用サーバーを安全に切り替えられず、起動中のライブ切替にも対応していません。切替時は後述の手順でBotを再起動してください。

## コマンド一覧

角括弧の引数は省略可能です。Botからの管理結果や個人データは、原則として実行者だけに見える応答で表示されます。

| コマンド | 利用者 | 説明 |
| --- | --- | --- |
| `/help` | 全員 | 利用できるコマンドと概要を、自分だけに表示します。 |
| `/briddle riddle answer [term] [winner_limit] [wrong_answers] [answer_limit] [media]` | 全員 | 指定人数の正解で回答受付を終了します。正解者・誤答の公開方法・回答回数を設定でき、スレッドは感想戦用に残ります。 |
| `/riddle riddle answer [term] [public_answers] [answer_limit] [media]` | 全員 | 期限式の問題を作成します。個人設定を問題ごとに上書きできます。 |
| `/ogiri theme [term] [answer_limit] [media]` | 全員 | 回答を公開し、出題者が設定済み絵文字で採用回答とMVPを選ぶ期限式の大喜利を作成します。 |
| `/hint riddle_id [text] [media]` | 作成者・管理者 | 受付中の問題へ、文章またはメディアのヒントをスポイラー形式で追加します。 |
| `/close riddle_id` | 作成者・管理者 | 受付中の問題を期限前でも締め切り、その時点の結果を発表します。スレッドは感想戦用に残ります。 |
| `/delete riddle_id` | 作成者・管理者 | 受付中・終了済みを問わず、問題投稿、回答スレッド、保存データを完全削除します。 |
| `/list` | 全員 | 自分が作成した問題の一覧を、自分だけに表示します。管理者にはサーバー内の全問題を表示します。 |
| `/pref prefid prefvalue` | 管理者 | サーバー単位のBot設定を変更します。 |
| `/mypref prefid prefvalue` | 全員 | 自分が作成する `/riddle` と `/ogiri` の個人既定値を変更します。 |
| `/status` | 全員 | Botの稼働状況を表示します。 |
| `/mydata` | 全員 | Botが保存している自分に関するデータを確認します。 |
| `/deletemydata confirm:true` | 全員 | 自分に関する保存データを削除します。 |

`riddle` は問題文、`answer` は正解です。`answer` に別解を登録する場合は、`シロナガスクジラ|blue whale` のように半角の `|` で区切ります。問題作成後、正解は終了時まで公開されません。

参加者は作成された公開スレッド内の「回答する」ボタンを押し、表示されたModalへ回答を入力します。`/briddle` では正誤結果が回答者本人だけに表示されます。`/riddle` では期限前に自動判定の正誤が推測されないよう、回答を受け付けたことだけが本人に表示され、結果は期限時に発表されます。`/ogiri` には固定の正解や自動正誤判定がなく、期限時に出題者が採用した回答者とMVPを発表します。

`/briddle` の `winner_limit` は、何人が正解したら回答受付を終了するかを表します。`1`〜`100`を指定でき、省略時は従来どおり`1`です。新しく正解したユーザーは直後にスレッドで発表され、その時点の出題者と、その問題へ1回以上回答した全ユーザーへ個別メンションします。人数が多い場合は50人ずつ複数メッセージに分割します。一時ロールは作成しません。回答前のスレッド案内とModalにも、回答すると関係者メンションの対象になることを表示します。回答本文と正解そのものは終了まで伏せられ、同じユーザーが正解を再送しても人数には重複加算しません。正解発表の送信が一時的に失敗した場合は1回再試行し、それでも失敗した場合は回答者本人へ通知します。正解記録自体は保持され、終了結果には表示されます。

`wrong_answers`では不正解だった回答文の扱いを選べます。

- `private`：公開せず、SQLiteにも保存しません。省略時はこの設定です。
- `immediate`：不正解と判定した直後に、回答者名と回答文をスレッドへ公開します。SQLiteには回答本文を保存しません。
- `after_close`：回答中は公開せず、正解人数の到達または期限で終了した時にまとめて公開します。再起動後も発表できるよう、回答本文を終了までSQLiteへ一時保存します。

`/briddle` の `answer_limit` は1人あたりの回答回数で、`1`〜`100`を指定できます。省略した場合、`wrong_answers:after_close` では一時保存データが無制限に増えないよう100回、それ以外では無制限です。

`/riddle` の `public_answers` を `true` にすると、回数上限内で受け付けた各回答をスレッドへ公開します。正解・不正解のどちらも公開しますが、自動判定の正誤は期限まで表示しません。上限を超えて拒否された回答は公開されません。`false` の場合は、ほかの参加者から回答本文は見えず、リアクションによる別解採用もできません。`/ogiri` の回答は常に公開されます。

その問題だけ他人の回答を見せる場合は、`/riddle` 実行時に `public_answers:true` を指定します。今後自分が作る `/riddle` で常に公開する場合は、先に `/mypref public_answers true` を実行します。個人既定値を設定した後でも、各 `/riddle` の `public_answers:false` で一時的に非公開へ戻せます。

Botは公開した回答に、サーバーで設定された正解採用絵文字（初期値✅）を1つ付けます。問題の出題者が期限までにその絵文字を押すと、`/riddle` では想定外の回答を正解として、`/ogiri` では面白い回答を採用として記録します。採用に成功するとBotが同じ回答へ🏆を付けます。出題者以外が付けた採用絵文字は記録されず、リアクション数が増えても公式な採用にはなりません。Botが付けた🏆が、正解・採用またはMVPをBotが記録した印です。採用済みのリアクションを外しても採用は取り消されません。

`/ogiri` の公開回答には、大喜利MVP絵文字（初期値👑）も付きます。出題者が期限までにこの絵文字を押した回答者は、Botの🏆が付き、終了結果のMVP欄へ表示されます。MVP選出だけでは採用回答者には追加されないため、同じ回答を両方へ載せる場合は採用絵文字とMVP絵文字をそれぞれ押します。出題者以外のMVP絵文字やリアクション数はMVP判定に使用しません。MVP絵文字を後から外しても選出は取り消されません。問題の開始メッセージには良問マーク絵文字（初期値⭐）が付き、参加者がDiscord上の目印として利用できます。

`answer_limit` は、1人の参加者がその問題へ回答できる回数です。`0` は無制限、`1`〜`100` は指定回数までを表します。`/riddle` で `public_answers` と `answer_limit` を省略すると、問題作成者の `/mypref` の値を使用します。`/ogiri` で `answer_limit` を省略した場合も同じ個人既定値を使用します。コマンドで値を指定した場合は、その問題だけを上書きし、個人設定自体は変更しません。

`media` には画像・音声・動画を1ファイルだけ指定できます。ファイル上限は25 MiBまたはDiscordサーバーのアップロード上限の小さい方です。SVGや種類を判定できないファイルは添付できません。この制限は問題とヒントのメディアに共通です。

`/hint` は受付中の `/briddle`、`/riddle`、`/ogiri` に何度でも使用できます。`text` は1,000文字以内で、`text` または `media` の少なくとも一方が必要です。文章は `||スポイラー||`、メディアはDiscordのスポイラー付き添付として回答スレッドへ投稿されます。Discordのスポイラーは、利用者がクリックするまで表示を隠すための機能であり、アクセス制御や暗号化ではありません。スレッドを閲覧できる利用者はヒントを開けます。

なぞなぞの結果には、問題作成から最初に正解として記録された回答の投稿までの所要時間を表示します。出題者が公開回答を別解として手動採用した場合も、その回答が投稿された時刻を使用します。結果発表後は新しい回答を受け付けませんが、スレッドへの通常メッセージ投稿は続けられるため、そのまま感想戦に利用できます。無操作状態が続くと、Discord標準の設定に従って自動アーカイブされます。

`/close riddle_id` を実行すると、`term` より前でもその時点で回答受付を終了し、通常の期限到達時と同じ形式で現在の結果を発表します。`/briddle` は現時点の正解者、正解、`wrong_answers:after_close` の公開待ち誤答を表示します。`/riddle` は現時点の正解者と正解、`/ogiri` はその時点までに採用された回答者とMVPを表示します。実行できるのは問題の作成者またはDiscordの管理者です。締切後も回答スレッドは感想戦用に開いたままです。

`term` は次のように、整数と単位を続けて指定します。

- `30m`: 30分
- `2h`: 2時間
- `1d`: 1日

省略時は24時間です。指定できる範囲は1分から30日までです。Discord上の日時は、各ユーザーのクライアントの言語・タイムゾーン設定に合わせて表示されます。

正解判定では大文字・小文字、全角・半角、空白の違いを正規化したうえで完全一致を確認します。部分一致ではありません。

1ユーザーが同時に作成できる未終了問題は、初期状態では最大10件です。管理者は `/pref` で変更できます。

### `/pref` の設定項目

| `prefid` | `prefvalue` | 初期値 | 説明 |
| --- | --- | --- | --- |
| `allowed_channel` | `current` / `none` / チャンネルID / チャンネルメンション | `none` | 出題できるチャンネルを制限します。`current` は実行中のチャンネル、`none` は制限解除です。 |
| `max_active` | `1`〜`100` | `10` | 1ユーザーが同時に保持できる未終了問題数です。 |
| `mention_winners` | `true` / `false` | `true` | 終了時に正解者をメンションするか設定します。 |
| `answer_accept_emoji` | Unicode絵文字 / サーバーのカスタム絵文字 | `✅` | 公開回答を正解・採用として選ぶ絵文字です。 |
| `ogiri_mvp_emoji` | Unicode絵文字 / サーバーのカスタム絵文字 | `👑` | `/ogiri` のMVPを選ぶ絵文字です。 |
| `good_question_emoji` | Unicode絵文字 / サーバーのカスタム絵文字 | `⭐` | 問題の開始メッセージへ付ける良問マークです。 |

Discordの「管理者」権限を持つメンバーだけが `/pref` を実行できます。

絵文字設定には、通常のUnicode絵文字か、そのサーバーで利用できるカスタム絵文字を指定できます。カスタム絵文字はDiscord上で入力した `<:名前:ID>` または `<a:名前:ID>` の形式を使用します。3種類の評価絵文字には、それぞれ異なる絵文字を設定してください。🏆はBotが評価を記録したことを示す公式マークとして予約されているため、3種類の設定には使用できません。

絵文字設定は問題を作成した時点で、その問題へスナップショットとして保存されます。`/pref` で変更した値は変更後に作成する問題へ反映され、既に受付中の問題で使われている絵文字は変わりません。

設定例は `/pref answer_accept_emoji ☑️`、`/pref ogiri_mvp_emoji 🥇`、`/pref good_question_emoji 💡` です。`/status` では、そのサーバーで現在設定されている3種類の絵文字を確認できます。

### `/mypref` の設定項目

| `prefid` | `prefvalue` | 初期値 | 説明 |
| --- | --- | --- | --- |
| `public_answers` | `true` / `false` | `false` | 自分が作成する `/riddle` で、受け付けた回答をスレッドへ公開するか設定します。 |
| `answer_limit` | `0` / `1`〜`100` | `0` | 自分が作成する `/riddle` と `/ogiri` の1人あたりの回答回数です。`0` は無制限です。 |

個人設定はサーバーごとに保存されます。`/mypref` の応答は実行者だけに表示されます。

### 個人データの削除

`/deletemydata` は誤操作防止のため、`confirm` に `true` を指定した場合だけ実行されます。実行すると、本人が作成した未終了問題は取り消されてスレッドが終了し、ほかの問題に保存された本人の正解者記録・回答回数・公開回答メッセージの対応情報・終了時公開待ちの誤答・個人設定も削除されます。この操作は元に戻せません。先に `/mydata` で対象を確認してください。

`public_answers:true` によってDiscordのスレッドへ公開済みの回答メッセージは、`/deletemydata` では削除されません。削除が必要な場合はサーバー管理者へ依頼してください。

### 問題の締切と完全削除

`/close riddle_id` は受付中の問題を締め切って現在の結果を発表します。問題投稿と回答スレッドは残り、スレッドは感想戦用に開いたままです。

`/delete riddle_id` は問題の状態や期限にかかわらず、問題投稿、回答スレッド、その中の公開回答とヒント、SQLiteの問題データを完全削除します。この操作は元に戻せません。Discord側の削除に失敗した場合はSQLiteのデータを保持するため、Botの権限を直して同じコマンドを再実行できます。

どちらの操作も、問題の作成者またはDiscordの「管理者」権限を持つメンバーだけが実行できます。Discord上で回答スレッドを手動削除した場合も、そのスレッドに紐付いたSQLiteの問題データを削除します。

## データとセキュリティ

- SQLiteデータベースには、問題の処理に必要なDiscordサーバーID・ユーザーID・問題・正解・期限・設定、問題作成時の評価絵文字スナップショットなどが保存されます。公開回答については、リアクション採用と再起動後の復旧に必要なDiscordメッセージID・問題ID・回答者ID・回答回数・投稿日時・採用日時・MVP選出日時の対応も保存します。`/briddle wrong_answers:after_close`を選んだ場合だけ、終了時公開待ちの誤答本文も一時保存します。
- 結果表示、必要な誤答公開、感想戦スレッドの再オープンが完了すると、正解者、回答回数、公開回答の対応、公開待ち誤答など、再判定に使う子データを削除します。問題本体の行は `finalized_at`、問題ID、Discordチャンネル・スレッド・メッセージIDの紐付けとともに保持し、`/delete` またはDiscord上での回答スレッド削除時に削除します。一時的なDiscord権限・通信エラーでは確定処理を完了扱いにせず、定期処理で再試行します。
- Botトークン、問題の正解、参加者がModalへ入力した回答本文はログへ出力しません。
- `/riddle public_answers:true` と `/ogiri` の回答本文はDiscordのスレッドへ投稿しますが、SQLiteやログには保存しません。
- `/briddle`の誤答本文は`private`と`immediate`ではSQLiteへ保存しません。`after_close`では終了時の一括公開に必要な期間だけSQLiteへ保存し、ログには出力しません。
- `.env` とSQLiteデータベースは `.gitignore` の対象です。
- `.env.example` には実際のトークンを記入しないでください。
- Botを同じデータベースに対して複数起動しないでください。
- このBotには自動バックアップ機能がありません。

既存のSQLiteデータベースは、更新後の初回起動時にスキーマバージョン5へ自動移行されます。既存の問題・正解者・回答回数・個人設定は保持され、問題へ手動締切時刻 `closed_early_at` と結果確定時刻 `finalized_at` が追加されます。データベースを削除したり作り直したりする必要はありません。重要な運用データがある場合は、Botを停止した状態で更新前にバックアップしてください。

Botがサーバーから削除された場合、そのサーバーのローカルデータは退出イベント受信時、または次回起動時の照合で削除されます。個人データは `/mydata` と `/deletemydata` で本人が確認・削除できます。Discord上に利用者自身が投稿したメッセージは、このローカルデータ削除の対象外です。

## 運用するDiscordサーバーを変更する

起動中のライブ切替には対応していません。次の順序で安全に変更します。

1. 旧サーバーで管理者が `/list` を確認し、未終了問題が終わるまで待つか、各問題を `/close riddle_id` で締め切ります。問題投稿と回答スレッドも不要なら `/delete riddle_id` で完全削除します。
2. Developer Portalの招待URLを使い、同じBotアカウントを必要な権限付きで新サーバーへ招待します。Botトークンの再発行は不要です。
3. 旧サーバーからBotを削除します。
4. `.env` の `DISCORD_GUILD_ID` を新サーバーのIDへ変更します。
5. Linuxではsystemdサービス、Windowsではタスクスケジューラのタスクを再起動します。
6. 新サーバーで `/help` と `/status` を実行します。
7. 新サーバーで `/status` の設定値を確認します。出題チャンネルを制限する場合は、そのチャンネルで管理者が `/pref allowed_channel current` を実行し、評価絵文字なども必要に応じて `/pref` で設定します。サーバー設定はサーバーごとなので、旧サーバーの設定は引き継がれません。

OS別の具体的な停止・編集・再起動手順は、[Windowsセットアップ](docs/WINDOWS_SETUP.md)または[Linuxセットアップ](docs/LINUX_SETUP.md)を参照してください。

## 変更をGitへ反映する

実装・テスト後に、プロジェクトのルートで差分を確認してからコミットします。`.env`、データベース、ログは追加しないでください。

```text
git status
git diff
git add README.md docs technical_requirements.txt riddle_bot tests
git commit -m "Add hints answer judging and ogiri"
git push origin main
```

`git add` には、実際に変更してコミットしたいファイルまたはディレクトリだけを指定します。`.env`、`data/`、ログ、Linux専用ユーザーの `.bash_history` や `.cache/` は追加しません。

運用環境で更新を取り込むときは、Botを停止してからリポジトリのルートで `git status` を確認し、`git pull --ff-only origin main` を実行します。その後、依存関係を再インストールしてBotを起動します。SQLiteのバージョン5への移行は新しいBotの初回起動時に自動実行されます。OSごとの正確な停止・更新・再起動コマンドは、[Windowsセットアップ](docs/WINDOWS_SETUP.md)または[Linuxセットアップ](docs/LINUX_SETUP.md)を参照してください。

## 24時間運用について

自宅PCで24時間動かす場合、BotはPCが起動し、スリープしておらず、ネットワークに接続されている間だけ稼働します。画面を消すだけなら問題ありませんが、スリープ・休止状態・シャットダウン中は応答できません。

Windowsではタスクスケジューラ、Linuxではsystemdを利用すると、OS起動時の自動開始と異常終了時の再起動を設定できます。具体的な設定はOS別セットアップ手順を参照してください。

## トラブルシューティング

### スラッシュコマンドが表示されない

- 招待時に `applications.commands` スコープを選択したか確認します。
- `.env` の `DISCORD_GUILD_ID` が対象サーバーのIDか確認します。
- Botを再起動し、コマンド同期のログを確認します。
- グローバル同期の場合は、Discord側への反映に時間がかかることがあります。

### 問題スレッドを作成できない

対象チャンネルで、Botに `View Channels`、`Send Messages`、`Create Public Threads`、`Send Messages in Threads`、`Read Message History`、`Manage Threads`、`Add Reactions` が許可されているか確認します。メディアを使用する場合は `Attach Files` も必要です。チャンネル固有の権限上書きにも注意してください。

### 設定した絵文字が付かない

`/status` で現在の絵文字設定を確認します。カスタム絵文字の場合は、その絵文字が対象サーバーに存在し、Botから利用できることを確認してください。既存問題には作成時の設定が保持されるため、`/pref` の変更は新しく作成した問題で確認します。解決しない場合はUnicode絵文字へ戻して試してください。

### Botがログインできない

`.env` の `DISCORD_TOKEN` が空でないか確認します。トークンを再生成した場合は `.env` を更新してBotを再起動します。トークンをログや問い合わせ文へ貼り付けないでください。

### 再起動後に二重応答する

同じBotを複数のターミナル、タスク、systemdサービスから起動していないか確認します。常に1プロセスだけを起動してください。
