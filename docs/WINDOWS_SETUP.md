# Windowsセットアップ手順

この手順では、Windows 10またはWindows 11の自宅PCでBotをセットアップし、タスクスケジューラから自動起動する方法を説明します。

## 1. 事前準備

### Pythonをインストールする

[Python公式サイト](https://www.python.org/downloads/windows/)からPython 3.11以上をインストールします。インストーラーでは、可能であれば `Add python.exe to PATH` を有効にしてください。

PowerShellを開き、バージョンを確認します。

```powershell
py -3 --version
```

`Python 3.11.x` 以上が表示されれば利用できます。`py` が見つからない場合はPythonを再インストールするか、インストール先の `python.exe` を直接指定してください。

### Gitを用意する

Gitからcloneまたは更新する場合は、[Git for Windows](https://git-scm.com/download/win)をインストールします。PowerShellを開き直して確認します。

```powershell
git --version
```

ZIPなどでソースを手作業配置し、Gitによる更新を行わない場合は必須ではありません。

### Discord Botを準備する

[READMEの「Discord側の準備」](../README.md#discord側の準備)に従い、Botの作成、招待、必要権限の設定を済ませます。

## 2. 仮想環境と依存パッケージ

PowerShellで、プロジェクトを配置したディレクトリへ移動します。次のパスは実際の配置先へ読み替えてください。

```powershell
Set-Location "C:\path\to\Riddles Discord Bot"
```

仮想環境を作成します。

```powershell
py -3 -m venv .venv
```

仮想環境のPythonを直接使って、pipと依存パッケージをインストールします。

```powershell
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

この手順では仮想環境を「有効化」しないため、PowerShellの実行ポリシーを変更する必要はありません。

## 3. 環境変数を設定する

サンプルを `.env` へコピーします。

```powershell
Copy-Item .env.example .env
notepad .env
```

内容を次のように設定します。

```dotenv
DISCORD_TOKEN=
DISCORD_GUILD_ID=
DATABASE_PATH=data/riddles.db
LOG_LEVEL=INFO
```

- `DISCORD_TOKEN=` の右側にDeveloper Portalで取得したBotトークンを入力します。
- `DISCORD_GUILD_ID=` の右側にコマンドを同期し、利用を許可するサーバーIDを入力します。
- 通常は `DATABASE_PATH` と `LOG_LEVEL` を変更する必要はありません。

Botトークンが入った `.env` を共有、添付、Gitへコミットしないでください。`.env.example` の `DISCORD_TOKEN` は常に空のままにします。

`DISCORD_GUILD_ID` はDiscord Gatewayへの接続先ではありません。同じBotアカウントを招待したサーバーへBot自体は接続しますが、この値はコマンドの同期先と利用可能なサーバーを指定します。起動中のライブ切替には対応していないため、変更後はタスクを再起動してください。

## 4. 手動で起動確認する

プロジェクトのルートディレクトリで次を実行します。

```powershell
.\.venv\Scripts\python.exe main.py
```

確認する項目:

1. ログにBotのログイン成功が表示される。
2. 対象サーバーで `/help` と `/status` が実行できる。
3. `/briddle`、`/riddle`、`/ogiri` で公開スレッドが作成される。
4. スレッド内の「回答する」ボタンから回答できる。
5. 問題投稿に良問マーク、公開回答に正解採用絵文字、`/ogiri` の回答にMVP絵文字が付き、出題者の採用操作へBotが🏆を付ける。
6. `/hint` で文章とメディアがスポイラー表示される。

停止する場合は、PowerShellで `Ctrl+C` を押します。

起動エラーが出た場合は、トークン、サーバーID、Bot権限、Pythonのバージョンを確認します。トークンをエラーログや問い合わせ文へ貼り付けないでください。

## 5. PCのスリープを防止する

Botを24時間動かすには、PCを起動したままにするだけでなく、スリープを無効にする必要があります。画面の電源は切れても問題ありません。

Windows 11:

1. 「設定」→「システム」→「電源とバッテリー」を開きます。
2. 「画面、スリープ、休止状態のタイムアウト」を開きます。
3. 少なくとも「電源接続時にデバイスをスリープ状態にする」を「なし」にします。

Windows 10では、「設定」→「システム」→「電源とスリープ」に同等の設定があります。

ノートPCは電源へ接続し、ふたを閉じたときの動作も「スリープしない」に設定してください。発熱、換気、停電、ルーター停止には注意してください。ディスプレイだけを自動消灯する設定は残して構いません。

管理者権限のPowerShellから、電源接続時の自動スリープを無効にすることもできます。

```powershell
powercfg /change standby-timeout-ac 0
powercfg /change hibernate-timeout-ac 0
```

これはPC全体の電源設定を変更します。ほかの用途への影響を理解したうえで使用してください。

## 6. タスクスケジューラで自動起動する

最初に手動起動が成功することを確認してから設定します。

1. `Win + R` を押し、`taskschd.msc` と入力してタスクスケジューラを開きます。
2. 右側の「タスクの作成」を選びます。「基本タスクの作成」ではなく詳細設定ができる方を使用します。
3. 「全般」タブを設定します。
   - 名前: `Riddles Discord Bot`
   - 24時間運用する場合: 「ユーザーがログオンしているかどうかにかかわらず実行する」
   - 「最上位の特権で実行する」は通常不要です。
4. 「トリガー」タブで「新規」を選びます。
   - タスクの開始: 「スタートアップ時」
   - ネットワーク起動待ちのため、必要なら30秒〜1分の遅延を設定します。
5. 「操作」タブで「新規」→「プログラムの開始」を選びます。
   - プログラム/スクリプト: `C:\path\to\Riddles Discord Bot\.venv\Scripts\python.exe`
   - 引数の追加: `main.py`
   - 開始: `C:\path\to\Riddles Discord Bot`
6. 「条件」タブを確認します。
   - 24時間運用では「コンピューターをAC電源で使用している場合のみタスクを開始する」の扱いを運用方針に合わせます。
   - 必要なら「タスクを実行するためにスリープを解除する」を有効にします。ただし、通常はスリープ自体を無効にする方が確実です。
7. 「設定」タブを設定します。
   - 「タスクが失敗した場合の再起動の間隔」を1分にします。
   - 再起動試行回数を3回以上にします。
   - 「タスクが既に実行中の場合に適用される規則」は「新しいインスタンスを開始しない」にします。
   - 長時間後にタスクを自動停止する設定は無効にします。
8. 「OK」を押します。Windowsアカウントのパスワードを求められた場合は入力します。

`プログラム/スクリプト` と `開始` には、実際の絶対パスを指定してください。`開始` が空だと `.env` や相対指定のデータベースを見つけられないことがあります。

### タスクをテストする

作成したタスクを右クリックして「実行」を選びます。対象サーバーで `/status` を実行し、応答することを確認します。

タスクスケジューラの「履歴」タブでは、起動の成否を確認できます。Bot自体の起動エラーを詳しく調べるときは、一度タスクを停止し、「4. 手動で起動確認する」のコマンドをPowerShellで実行してください。

### 設定変更・更新後

`.env` やコード、依存パッケージを更新する場合は、最初にタスクスケジューラで `Riddles Discord Bot` を右クリックし、「終了」を選びます。Botが停止したことを確認してから作業してください。

Gitから更新する場合は、PowerShellでプロジェクトルートへ移動し、現在の場所がGitリポジトリとして認識されることを確認します。

```powershell
Set-Location "C:\path\to\Riddles Discord Bot"
git rev-parse --show-toplevel
```

プロジェクトルートのパスが表示されれば更新できます。`fatal: not a git repository` と表示された場合は更新を進めず、プロジェクト直下に `.git` があるか確認してください。既存の `.env` や `data` フォルダーを消したり、運用ディレクトリへ別のリポジトリを重ねてcloneしたりしないでください。

重要な運用データがある場合は、停止中に `data\riddles.db` を別名または別の安全な場所へコピーしてから更新します。その後、ローカル状態と取得予定のコミットを確認し、fast-forwardだけを許可して更新します。

```powershell
git status --short
git fetch origin
git log -1 --oneline origin/main
git pull --ff-only origin main
```

追跡済みファイルの変更や競合が表示された場合は、`pull` を実行せずその内容を確認してください。`git reset --hard` で消さないでください。また、`.env`、`data`、ログなどの運用ファイルを `git add` しないでください。

依存パッケージを更新します。

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

タスクスケジューラで同じタスクを右クリックし、「実行」を選びます。新しいBotの初回起動時に、既存のSQLiteデータベースはスキーマバージョン4へ自動移行されます。既存の問題、正解者、回答回数、サーバー設定、個人設定は保持され、既存の`/briddle`は1人正解・誤答非公開として継続されます。`data\riddles.db` を削除したり空のDBへ置き換えたりしないでください。

起動後に `/help` と `/status` を確認します。起動に失敗した場合はタスクを停止し、「4. 手動で起動確認する」のコマンドを実行してエラーを確認してください。同じBotを手動起動とタスクスケジューラの両方から同時に動かさないでください。

## 7. 運用するDiscordサーバーを変更する

未終了問題を残したまま切り替えないでください。次の順序で操作します。

1. 旧サーバーで管理者が `/list` を確認し、未終了問題が終わるまで待つか、各問題を `/delete riddle_id` で取り消します。Discord上の問題投稿と回答スレッドも消す場合は、受付中に `/delete riddle_id purge:true` を使用します。
2. Developer Portalの招待URLを使い、同じBotアカウントを必要な権限付きで新サーバーへ招待します。
3. 旧サーバーからBotを削除します。
4. タスクスケジューラで `Riddles Discord Bot` を右クリックし、「終了」を選びます。
5. プロジェクトルートで `.env` を開き、`DISCORD_GUILD_ID` だけを新サーバーのIDへ変更して保存します。Botトークンの変更・再発行は不要です。

```powershell
notepad .env
```

6. タスクスケジューラで同じタスクを右クリックし、「実行」を選びます。
7. 新サーバーで `/help` と `/status` を実行します。
8. `/status` でサーバー設定を確認します。出題チャンネルを制限する場合は、そのチャンネルで管理者が `/pref allowed_channel current` を実行し、評価絵文字なども必要に応じて `/pref` で設定します。

`/pref` の設定はサーバーごとに保存されるため、新サーバーでは出題チャンネル、評価絵文字、その他の設定を確認してください。`.env` の書き換えだけで起動中の接続先をライブ切替することはできません。

## 8. アンインストール・トークン失効

運用を終了する場合は、タスクスケジューラのタスクを無効化または削除し、Botプロセスを停止します。Botを今後使用しない、またはトークン漏えいが疑われる場合は、Discord Developer Portalの `Bot` 画面でトークンを再生成してください。
